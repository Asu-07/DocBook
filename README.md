# DocBook

Multi-role healthcare appointment booking platform.

- **Frontend** — Angular 21 (standalone components + signals), SCSS
- **Backend** — Python 3.13, FastAPI, SQLAlchemy, JWT auth
- **Browser-side ML** — `@vladmandic/face-api` for the doctor Face ID portal
- **Demo data** — 18 partner hospitals across 10 Indian cities, 50 doctors, 25 patients, 80 appointments

---

## Local development

```bash
# Backend
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
# source .venv/bin/activate && pip install -r requirements.txt  # macOS/Linux
python seed_demo.py
python -m uvicorn main:app --reload

# Frontend (separate terminal)
cd frontend
npm install
npm start
```

Then http://localhost:4200/. The Angular dev server proxies `/api/*` to the FastAPI server on `:8000` via [proxy.conf.json](frontend/proxy.conf.json), so no CORS setup is needed locally.

## Production deployment — Render (backend) + Vercel (frontend)

The clean split: FastAPI runs as a real long-running web service on Render (no cold starts), and the Angular static bundle ships from Vercel's CDN.

### Step 1 — Backend on Render

1. Sign in to [render.com](https://render.com) and click **New → Blueprint**.
2. Connect this GitHub repo (`Asu-07/DocBook`). Render will auto-detect [render.yaml](backend/render.yaml).
3. The blueprint will create a web service named `docbook-backend`. Render will prompt for two env values:
   - **DATABASE_URL** — paste a PostgreSQL connection string. The simplest option is to also create a free Render Postgres in the same blueprint and link it. Or use Neon / Supabase / a PG you already have.
   - **CORS_ORIGINS** — leave blank for now; you'll fill it in once you have the Vercel URL.
   - `SECRET_KEY` is auto-generated by Render.
4. Wait ~5 min for the first build. The service will be at `https://<service-name>.onrender.com`.
5. **Seed the database once** — open the Render Shell tab for the service and run:
   ```bash
   python seed_demo.py
   ```
   Then create the admin account:
   ```bash
   python -c "from passlib.context import CryptContext; from database import SessionLocal; from models.user import User; pwd=CryptContext(schemes=['bcrypt']); db=SessionLocal(); db.add(User(name='DocBook Admin', email='admin@docbook.local', password_hash=pwd.hash('Admin123!'), role='admin')); db.commit()"
   ```
6. Verify: `curl https://<service-name>.onrender.com/health` should return `{"status":"ok"}`.

### Step 2 — Point the frontend at the deployed backend

Edit [frontend/src/environments/environment.prod.ts](frontend/src/environments/environment.prod.ts) and replace the URL with your actual Render service URL:

```ts
export const environment = {
  production: true,
  apiBaseUrl: 'https://<your-render-service>.onrender.com/api/v1',
};
```

Commit and push:

```bash
git add frontend/src/environments/environment.prod.ts
git commit -m "Wire prod frontend to deployed backend"
git push
```

### Step 3 — Frontend on Vercel

The repo includes a [vercel.json](vercel.json) at the root that configures Vercel to build only the Angular frontend.

1. Go to [vercel.com/new](https://vercel.com/new) and import `Asu-07/DocBook`.
2. Vercel will read `vercel.json` automatically. The form should show:
   - Framework Preset: **Angular**
   - Build Command: `cd frontend && npm install && npm run build`
   - Output Directory: `frontend/dist/frontend/browser`
   - Install Command: `cd frontend && npm install`
3. Click **Deploy**. First build takes 2-3 min.
4. You'll get a URL like `https://doc-book.vercel.app`.

> **Alternative**: instead of using `vercel.json`, you can click **Edit** next to "Root Directory" in the Vercel UI and change it to `frontend`. Vercel then detects the Angular app directly — no `vercel.json` needed. Pick whichever you prefer.

### Step 4 — Allow CORS from the Vercel domain

Back on Render, open the backend service → **Environment** → set:

```
CORS_ORIGINS = https://<your-vercel-domain>.vercel.app,https://doc-book.vercel.app
```

(Add any custom domains you've configured.) Render redeploys automatically.

### Step 5 — Smoke test the live deployment

```bash
curl https://<vercel-domain>/                                                # Angular SPA
curl https://<render-service>.onrender.com/api/v1/stats/public               # API
curl https://<render-service>.onrender.com/api/v1/hospitals/regions          # API
```

Open the Vercel URL → log in as a doctor → set up Face ID → sign out → sign back in via Face ID. End-to-end works.

## Architecture notes

- **Auth** — JWT with bcrypt. Three login portals (`/login`, `/doctor/login`, `/hospital/login`) hit the same `/auth/login` endpoint; the frontend role-routes after the response.
- **Face ID** — `@vladmandic/face-api` runs in the browser. The 128-float descriptor is stored in `users.face_descriptor`; the backend compares with Euclidean distance (threshold 0.55). No raw images leave the browser.
- **Migrations** — `main.py` runs idempotent `_ensure_*_column` helpers at startup that `ALTER TABLE` if columns are missing. Safe to run on every cold start.
- **Frontend bundle** — ~640 KB main + lazy-loaded face-api models (~7 MB) only fetched when Face ID is opened.
- **Audit script** — [backend/scripts/full_audit.sh](backend/scripts/full_audit.sh) hits all 66 routes against a running backend; rerun anytime to verify health.

│   ├── src/app/components/     # Shared: navbar, footer, chatbot, face-capture, doctor-card, toast
│   ├── src/app/services/       # ApiService, FaceRecognitionService

│   └── proxy.conf.json         # Local /api proxy → :8000
├── vercel.json                 # Vercel: build only the frontend
└── README.md                   # You are here
